YUME For internet freedom.

Reach the internet through a server you control. YUME carries TCP, UDP and IP packets inside one encrypted connection that looks like Chrome visiting a website, with post-quantum keys. Run the yume client and yumed server, or embed the same engine through its C library.

Yume (夢) means dream in Japanese. The dream behind it is internet freedom for everyone. Security comes first, then stealth, then usable speed.

How it works

Your application's data is sealed by YTP/1, YUME's own protocol, then wrapped in WebSocket, HTTP/2 and TLS. The connection opens the way a captured Chrome visit does. Admission, authentication and the server's policy decide which traffic can pass.

Client and server

yume takes traffic from SOCKS5 (TCP and UDP), local forwards or a managed Linux TUN device. yumed serves the cover site and the tunnel on one port, and opens only the destinations its policy allows.

Circuits

TCP connections can leave through two or three servers in one operator's cluster, with separate keys on every hop. The client takes a shorter route only with the user's approval.

Speed

Tuning presets trade traffic shape for speed. On emulated 40 to 200 ms paths, one download through balanced kept about 95 % of the untunnelled rate, and the default stealth about 41 %. See the presets.

C library

libyume runs the same endpoint inside another program: authenticated named streams, packet channels, and routed TCP and UDP. Its interface can still change between development versions.

Desktop and Android

yume-gui imports kits and starts, stops and watches clients on Linux. The Android app runs native YTP/1 through the C library.

Modules

yumed hands a service's streams to a separate program over a private UNIX socket. The Debian package runs each module as its own user, without network access.

What protects a session

YTP/1 accepts one set of algorithms and nothing else, so an attacker on the path cannot push a session to a weaker or classical-only mode. This is the suite as the protocol spells it.

Classical and post-quantum together

Session keys combine X25519, ML-KEM-1024, a 32-byte key unique to each client and a secret from the TLS connection. Reading a session means breaking both key exchanges and stealing that client's key.

Recorded traffic stays sealed

ML-KEM-1024 and ML-DSA-87 are in NIST's highest security category, as hard to break as an AES-256 key. By default each direction replaces its keys at least every 1 MiB, 512 records or 500 ms of sending, each time through a fresh ML-KEM-1024 exchange, so traffic recorded today stays protected if a quantum computer later breaks X25519.

An ordinary website to everyone else

Without a valid admission proof, yumed is a static HTTPS site: GET and HEAD serve its pages, and other methods get 405. The proof is bound to the TLS connection and refused if replayed.

What the server still sees

yumed ends the tunnel, so it knows which client connected and where its traffic goes. HTTPS inside the tunnel keeps page content private from it, as on any network.

The threat model says what an attacker has to break and what each party can see. The stealth reference covers the browser profile and the captures behind it.

Run a tunnel

These steps from the quick start run a server and a client on Linux x86-64. A public server needs a DNS name, a trusted certificate and its own cover site, as the operations guide describes.

  1. Build

    ezbuild.sh prepares the pinned, patched OpenSSL and builds into build/bin. The contributor guide lists what the build needs.

    git clone https://github.com/FixCraft-Inc/yume.git
cd yume
./ezbuild.sh

  2. Create a kit

    yume-setup writes a server folder and a client folder: identities, keys, TLS material, configuration and a cover site. The client folder holds private keys, so move it over a trusted channel or seal it into one file with yume --seal-kit.

    build/bin/yume-setup init \
  --host yume.example.com --port 8443 \
  --output "$PWD/yume-kit" --client-name laptop

  3. Start the server

    Check the configuration, then serve the cover site and the tunnel on one port.

    build/bin/yumed --config yume-kit/server/yumed.json --validate
build/bin/yumed --config yume-kit/server/yumed.json

  4. Connect

    The client listens for SOCKS5 on 127.0.0.1:1080 and reconnects by itself if the session drops.

    build/bin/yume --config yume-kit/client/yume.json
curl --socks5-hostname 127.0.0.1:1080 https://example.com/

Other ways to install

Debian packages

yume carries the client, setup and doctor tools. yume-daemon carries the server and a hardened systemd unit that stays disabled until you install a kit.

Packaging guide

Release builds

Linux builds will appear on GitHub with checksums and a signed manifest. There is no release yet, so build from source.

Desktop GUI

Build yume-gui with -DYUME_BUILD_GUI=ON and Qt 6.4 or later. It imports kits and controls each client through its control socket.
